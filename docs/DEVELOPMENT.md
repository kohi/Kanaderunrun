# 開発・検証・配備ガイド

## セットアップ

Node.js 22.12以上の22系または24系とnpmを使用します。依存関係は `package-lock.json` に固定されているため、通常は `npm ci` でインストールしてください。APIキー・環境変数・バックエンドの設定は不要です。

```bash
npm ci
npm run dev
```

別端末から試す場合は `npm run dev -- --host 0.0.0.0` で待ち受けできますが、LAN内のHTTP URLではWebCodecsなどが利用できない場合があります。出力確認はlocalhostまたはHTTPSで行ってください。

## ソース構成

| パス | 内容 |
| --- | --- |
| `src/App.tsx` | 編集状態、画面遷移、確定前の楽曲と確定した楽曲、保存・復元 |
| `src/components/` | 楽曲編集、セクション構成、素材配置、動画編集、プレビュー、出力画面 |
| `src/types/project.ts` | プロジェクト・素材・タイムラインの型 |
| `src/core/timeline/` | 尺の配分、章の連結、表示対象の選択 |
| `src/core/audio/` | 楽曲解析、トリミング、再生、共通音声スケジュール |
| `src/core/video/` | 動画の読み込み・音声取得・フレーム取得 |
| `src/core/renderer/` | Canvas描画・映像効果 |
| `src/core/exporter/` | H.264/AACエンコードとMP4生成 |
| `src/core/utils/` | 画像読込、素材操作、IndexedDB保存、リソース解放 |
| `src/tests/` | Vitestの回帰テスト |
| `public/.htaccess` | Apache向けHTTPSリダイレクト・MIME・キャッシュ設定 |

## 必須チェック

```bash
npm test
npm run lint
npm run build
```

2026-09-21時点で7ファイル・76テストがあります。対象は音声解析とトリミング、時間配分、セクション合成、音声フェード、写真解析、乱数の再現性、素材編集の分離、保存データの直列化です。単体テストだけでは実ブラウザの動画デコード・WebCodecs・IndexedDBの一連の操作は検証しきれません。

## ブラウザでの回帰確認

Chromeで、個人データを含まない小さなテスト素材を使います。

1. 楽曲未選択ではセクション構成へ進めないことを確認します。
2. 音楽を読み込み、トリミングして上部ナビまたは確定ボタンから進みます。
3. セクションを追加し、自動配分と手動秒数を混在させます。再トリミングの確定後に残り時間だけが再計算されることを確認します。
4. 時間の余り・不足、未設定の表紙、空セクションがある場合に書き出しを止めることを確認します。
5. 各セクションへ異なる写真を入れ、読み込み途中にも別セクションへ移動します。素材が開始元にだけ追加されることを確認します。
6. カードのドラッグ並べ替えと、外部画像1枚による差し替えを確認します。別章からのカード移動や複数画像の差し替えドロップは受け付けないことを確認します。
7. 「効果だけおまかせ」で順番・秒数が維持されることを確認します。
8. 動画を追加・トリミングし、元音声の音量を変更します。章の前後で写真や動画が混入しないことを確認します。
9. 編集状態を保存し、ページを再読み込みして復元します。音楽・写真・動画・順番・効果・手動秒数を確認します。
10. 通し再生、章へのシーク、停止・再開、MP4書き出し、キャンセル後の再出力を確認します。生成したMP4も再生します。

上記の主要操作は開発時にChromeで確認済みです。ブラウザ自動操作スクリプトやテスト用の音楽・画像・動画はこのリポジトリに含めていません。

## 実装を変更するとき

- 非同期の素材編集はセクションIDと素材IDに結び付け、現在選択中の章や古い配列インデックスへ依存させないでください。
- 尺の配分は `durationPlan.ts`、全体タイムラインは `sections.ts` に集約します。画面だけで計算を変えると出力との不一致を招きます。
- プレビューとMP4の音声は共通スケジュールを維持します。
- 元ファイルから再生成できるブラウザオブジェクトを保存形式に追加しないでください。形式変更時はバージョンと互換性を検討してください。
- 素材の削除・置き換え時は画像リソースやBlob URLを解放します。

## 静的サイトへの配備

1. `npm ci` と必須チェックを実行します。
2. `npm run build` で `dist/` を生成します。
3. `dist/` の内容を配備先にコピーします。Apache環境では隠しファイルの `.htaccess` も含めます。
4. HTTPSを有効にし、実際の公開URLで素材の読み込みとMP4出力を確認します。

Viteの `base` は `./` です。ドメイン直下・サブフォルダのどちらにも配置できます。Apache以外のホストは `.htaccess` を解釈しないため、HTTPSなどはホスト側で設定してください。リバースプロキシ下では同梱のHTTPSリダイレクトが環境に合うか確認してください。

`npm run preview` はビルド確認用です。本番公開には静的ホスティングを使用します。このリポジトリには自動デプロイ設定はありません。

## 保存データとURLの変更

IndexedDBはブラウザとオリジン（プロトコル・ホスト・ポート）ごとに分離されます。`localhost` と `127.0.0.1`、開発用URLと公開URLでは同じ保存データを参照できません。配備先を変更してもブラウザ内の編集状態は自動移行されません。

## 既知の制約

- 保存は1件のローカルスナップショットで、クラウド同期やプロジェクトファイル出力はありません。
- 動画の元音声はブラウザがデコードできる場合のみ使用できます。
- 映像・音声・MP4の生成データをメモリに保持するため、長い動画や多量の素材では端末の制限を受けます。
- Viteは500kBを超えるバンドルの警告を出します。現状はビルド成功を妨げません。
